# VERTEX SAP GUI MCP

## Цель

**VERTEX SAP GUI MCP** — MCP-сервер для безопасного управления уже открытым SAP GUI for Windows из AI-клиентов, таких как Codex, Claude Code или Copilot. Он превращает SAP GUI Scripting API в небольшой, контролируемый набор инструментов: агент может переходить к транзакциям, находить и заполнять поля, нажимать кнопки, читать таблицы и фиксировать результат работы.

Первая цель проекта — надёжный, прозрачный прототип для ограниченного набора бизнес-сценариев. Универсальный автономный агент для всех экранов SAP — последующий этап: SAP GUI содержит нестандартные элементы, ALV, деревья, модальные окна и сообщения об ошибках, которые требуют специальных адаптеров и контроля.

## Архитектура

```text
Codex / Claude Code / Copilot
              |
              | MCP (локальный процесс)
              v
+-----------------------------------+
|          VERTEX SAP GUI MCP       |
|                                   |
|  session | screen | controls      |
|  input   | actions | table reader |
|  policy  | audit   | confirmations|
+----------------+------------------+
                 |
                 | Python API
                 v
       SAP GUI Scripting COM API
                 |
                 v
        SAP GUI for Windows
                 |
                 v
           SAP ECC / SAP S/4HANA
```

Сервер не хранит бизнес-логику в промпте. Он предоставляет предсказуемые операции над активной SAP-сессией, а AI-клиент выбирает последовательность вызовов и интерпретирует результаты. Каждая операция возвращает структурированный результат: состояние экрана, найденные контролы, системное сообщение, ошибку и, при необходимости, снимок экрана.

## Технологический стек

| Слой | Технология | Назначение |
| --- | --- | --- |
| AI-клиент | Codex, Claude Code, Copilot | Планирует действия и вызывает MCP-инструменты |
| Интеграция | Model Context Protocol (MCP) | Стандартизированный интерфейс локальных tools |
| Сервер | Python 3.11+ | Оркестрация, политики, аудит, модели данных |
| Windows COM | `pywin32` / `pythoncom` | Доступ к COM-объектам SAP GUI |
| Автоматизация | SAP GUI Scripting API | Работа с сессиями и элементами SAP GUI |
| Наблюдаемость | JSON-логи, снимки, correlation ID | Аудит и отладка сценариев |

SAP GUI Scripting должен быть разрешён на стороне SAP-сервера и в SAP GUI for Windows. Сервер подключается только к уже авторизованной пользовательской сессии; он не должен принимать или хранить логины и пароли.

## Набор MCP tools

Минимальный, безопасный контракт можно начать со следующих инструментов.

| Tool | Назначение |
| --- | --- |
| `sap_connect` | Находит доступные SAP GUI connection/session и выбирает сессию по явному идентификатору. |
| `sap_get_screen` | Возвращает транзакцию, заголовок окна, строку статуса, модальные окна и краткое дерево элементов. |
| `sap_find_controls` | Ищет контролы по техническому ID, типу, метке или шаблону. |
| `sap_set_text` | Записывает значение в поле после проверки, что поле доступно для ввода. |
| `sap_open_infotype` | Открывает инфотип PA30 по номеру или видимому названию, без сохранения данных. |
| `sap_press` | Нажимает кнопку, элемент toolbar или menu item по разрешённому ID. |
| `sap_select` | Выбирает значение в combo box, radio button, tab или списке. |
| `sap_send_vkey` | Отправляет ограниченный набор виртуальных клавиш SAP GUI, например Enter или Back. |
| `sap_transaction` | Переходит к транзакции из allowlist; возвращает результат навигации. |
| `sap_read_table` | Читает ALV/table control с ограничениями на объём данных. |
| `sap_read_tree` | Читает и раскрывает разрешённые узлы SAP tree control. |
| `sap_get_message` | Возвращает последнее системное сообщение: тип, номер и текст. |
| `sap_capture` | Создаёт снимок текущего окна для диагностики при явном разрешении. |
| `sap_confirm` | Подтверждает действие повышенного риска с одноразовым токеном пользователя. |

На раннем этапе полезно разделить tools на read-only и write/action. Это позволяет запускать AI сначала в режиме наблюдения и тестировать распознавание экранов без изменения данных.

## Безопасность и контроль

- Использовать только уже открытую интерактивную SAP-сессию; не передавать учётные данные через MCP.
- Разрешать транзакции, системные команды, таблицы и действия через allowlist, привязанную к роли пользователя.
- По умолчанию запускать режим **read-only**; действия записи включать отдельной конфигурацией.
- Требовать явного подтверждения перед сохранением, проводкой, удалением, отправкой сообщений и массовыми изменениями.
- Ограничить чтение строк ALV, экспортов и содержимого полей, чтобы не передавать лишние персональные или коммерческие данные в AI-клиент.
- Вести неизменяемый аудит: пользователь, сессия, tool, параметры с маскированием секретов, результат, время и correlation ID.
- Ставить таймауты, лимиты повторов и проверку ожидаемого состояния экрана после каждого изменяющего действия.
- Не выполнять произвольные SAP-команды, VBScript или Python-код, пришедшие от модели.

## Этапы реализации

1. **Подключение и наблюдение.** Реализовать обнаружение SAP GUI-сессии, `sap_connect`, `sap_get_screen`, поиск контролов и чтение статуса. Проверить на одной тестовой системе.
2. **Базовые действия.** Добавить ввод, нажатия, выбор значений и переход к транзакциям из allowlist; после каждого действия сверять экран и статусное сообщение.
3. **Сценарии и адаптеры.** Реализовать чтение ALV, tree controls и обработку pop-up-окон. Описать 2–3 конкретных бизнес-потока в виде тестов.
4. **Политики и аудит.** Ввести роли, read-only/write режимы, подтверждения, журналирование, маскирование данных и лимиты.
5. **Надёжность.** Добавить классификацию типовых ошибок, восстановление после ожидаемых экранов, снимки для диагностики и регрессионные тесты.
6. **Agent workflow.** Подключить MCP-клиент, дать ему описание tools и шаблоны сценариев. Только после стабильности детерминированных сценариев добавлять planner и vision fallback.

## Пример сценария

Задача: проверить открытые заказы по клиенту в разрешённой транзакции и вернуть краткую сводку без изменения данных.

```text
1. sap_connect(session_id="...")
2. sap_transaction(code="VA05")
3. sap_get_screen()
4. sap_find_controls(query="Sold-to party")
5. sap_set_text(control_id="...", value="10001234")
6. sap_press(control_id="...execute...")
7. sap_get_message()
8. sap_read_table(table_id="...", max_rows=100)
9. AI-клиент агрегирует только нужные поля и показывает пользователю сводку.
```

В write-сценарии перед шагом, который сохраняет или проводит документ, сервер должен вернуть требование подтверждения. AI-клиент показывает пользователю понятное описание изменения, получает одобрение и передаёт одноразовый токен в `sap_confirm` или в защищённый action tool.

## Сравнение с SAP Voyager

| Аспект | VERTEX SAP GUI MCP | SAP Voyager |
| --- | --- | --- |
| Основная идея | Тонкий управляемый MCP-слой над SAP GUI Scripting | Более широкая агентная система с планированием, самокоррекцией и vision fallback |
| Стартовая сложность | Низкая: Python, COM и явные tools | Выше: нужен агентный контур и дополнительные механизмы восстановления |
| Предсказуемость | Высокая для ограниченного allowlist сценариев | Зависит от planner, моделей и визуального распознавания |
| Подход к внедрению | Сначала детерминированные workflows и аудит | Ориентация на более автономное выполнение задач |
| Когда выбирать | Внутренний инструмент, PoC, контролируемые операции, интеграция с Codex/Claude Code | Когда нужны универсальнее навигация, auto-correction и обработка сложных экранов |

VERTEX SAP GUI MCP не пытается сразу заменить SAP Voyager. Он создаёт более простой и контролируемый фундамент: надёжные инструментальные вызовы, политика доступа и наблюдаемость. Planner, auto-correction и vision fallback можно добавлять поверх него, когда базовые SAP-сценарии станут измеримо стабильными.

## Первый запуск и настройка MCP

При первом доступе SAP GUI может показать пользователю окно разрешения Scripting.
Сервер ожидает появления Scripting Engine до 25 секунд и повторяет попытку
подключения, поэтому подтверждение окна не требует повторного вызова tool.
Таймаут меняется переменной окружения `VERTEX_SAP_CONNECT_TIMEOUT` (в секундах).
Инструменты просмотра (`sap_list_sessions`, `sap_status`, `sap_get_screen`,
`sap_find_controls`) доступны всегда. Переходы, ввод и нажатия по умолчанию
выключены. Только при осознанной необходимости добавьте
`VERTEX_SAP_ENABLE_ACTIONS: "1"` в `env` MCP-конфигурации.

После включения действий в PA30 можно открыть инфотип номером или его
видимым названием: `sap_open_infotype(infotype="0004")` либо
`sap_open_infotype(infotype="Challenge")`. Для названия инструмент находит и
выделяет совпадающую строку текущего меню PA30, без подмены на статический
код; это поддерживает локализованные и клиентские названия. По умолчанию он открывается в
режиме просмотра; `mode="change"` и `mode="create"` лишь открывают экран и
не сохраняют запись.

Используйте абсолютный путь к тому же `python.exe`, из которого успешно
запускается `check_sap.py`. Пример конфигурации приведён в `mcp.json.example`.
После изменения MCP-конфигурации перезапустите MCP-сервер (обычно достаточно
перезапустить Codex) и вызовите `sap_list_sessions`.
